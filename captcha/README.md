# Par'Axis — Users module: CAPTCHA + security (member 5)

The login form is protected by a **CAPTCHA image** generated by PHP (GD), plus the other security pieces of member 5: CSRF token on every form, brute-force lockout (5 failures = 15 min), hardened session cookie.

This folder is **independent**: it contains only this part of the Users module + the shared base needed to run it
(database connection + automatic tables, `User` model, login / logout, CSRF protection, layouts).
The other parts of the module are not in this folder (no page, no link).

## My files

| File | Role |
|---|---|
| `app/Security.php` | CSRF token, CAPTCHA (built-in image or Google reCAPTCHA), brute-force lockout, password rules |
| `app/Controllers/CaptchaController.php` | route `captcha`: draws the PNG image (SVG if GD is off), code kept hashed in the session |
| `app/Models/LoginAttempt.php` | failed logins per email / IP (table `login_attempts`) |
| `index.php` | session hardening: strict mode, HttpOnly + SameSite cookie |

Shared base (same in every part): `index.php`, `app/config.php`, `app/Database.php` + `app/Schema.php` (creates the tables), `app/helpers.php`, `app/Security.php`,
`app/Auth.php`, `app/Models/User.php`, `AuthToken.php`, `LoginAttempt.php`, `Controllers/Controller.php`, `LoginController.php`,
the layouts (`front-layout.php`, `layout.php`, `includes/`, `partials/`) and the CSS / JS.

## Database
Tables of this part: `users`, `auth_tokens`, `login_attempts`.

**Nothing to import.** Just start **MySQL** in XAMPP: at the first visit the site creates the database `paraxis`,
the tables of this part (`app/Schema.php`, `CREATE TABLE IF NOT EXISTS`) and 2 demo accounts.
The database login is in `app/config.php` (XAMPP default: user `root`, empty password).

## Run
- XAMPP: copy the folder `paraxis-users-captcha` into `htdocs`, open http://localhost/paraxis-users-captcha/index.php
- or `php -S localhost:8000` in this folder, then open http://localhost:8000/index.php

The project opens directly on its own page. When you are logged in, the **Log in** page shows who you are (name, role, email confirmed) with a **Log out** button.

## Scenario to test
1. Open **Log in**: the security image is under the password. Click **↻** to get another image.
2. Type a **wrong code** with the right password (`customer@paraxis.demo` / `Customer123!`) → *The security code is not correct* and a new image is shown.
3. Type the right code → you are logged in (the Log in page shows *You are logged in*).
4. Each image works **once** and expires after 10 minutes: reload the page, wait, or reuse an old code → refused.
5. Brute force: 5 wrong passwords for the same email → *Too many attempts, try again in 15 minutes* (table `login_attempts`).
6. CSRF: send the form without the hidden `csrf_token` (e.g. remove it with the browser tools) → refused.
7. Settings: `app/config.php` → `'captcha' => ['driver' => 'builtin' | 'recaptcha' | 'off']`.

## Security used in this part
- `password_hash()` / `password_verify()`, prepared statements (PDO), tokens stored **hashed** (sha256).
- CSRF token in every POST form (`Security::csrfField()` + `Security::checkForm()`).
- `session_regenerate_id()` at login / logout, HttpOnly + SameSite session cookie.
